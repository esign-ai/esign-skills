# 提问与答案处理规则

仅用于主流程明确列出的必要提问节点。先复用当前有效信息，再按依赖组织问题；不因支持提问工具增加业务步骤。

## 组织当前可问的问题

1. 扫描当前任务真正缺失的信息，已知不问。只有出现条件、问法和选项均可确定，且不依赖本批其他未知答案的问题，才放进同一批。
2. 若 B 依赖 A，而 C 与 A 独立，先问 A、C，收到实际提交后再决定 B。不因遇到 B 而延后 C，也不提前猜 B 的候选。
3. 同一决定只问一次，不将多个独立决定塞进一个复合问题。题数由实际缺口决定，可以只有一项，不凑题、不固定轮次、不提前问后续阶段的问题。
4. 缺文件只引导提供；取得并读取选定文件后才能组织依赖其内容的问题。对象选择与依赖所选对象的问题不合批。

## 使用实际提问能力

- 按本次真实工具定义构造参数，不指定工具名或猜字段。区分一道题的多选与一次调用承载多道题：支持本批问题数量和所需回答方式时，一次传入本批问题；只有一道题时可用单题能力。
- 工具不支持整批问题、缺少所需回答方式或不可用时，用一条简短文字消息列出同批必要问题，统一接收回复。不连续调用多个单题工具模拟批量，不试错猜参数，不向用户解释内部适配过程。
- 文件上传及各业务分支规定的开放填写、模板选择和最终确认仍沿用原方式；不将开放信息改成虚构选项，不先问“是否填写”再收内容。
- 等待用户实际提交；预选、空返回、超时、关闭界面不是答案。用户以普通文字给出明确答案直接处理，不要求必须点击；提问结果不明时先核对是否已展示或收到回复，不重复发问。

## 选项和答案

- 问法简短，选项易区分；对象候选必须来自用户或真实数据，保存选项与对象、版本、范围的映射。只展示必要名称或业务信息，不展示内部 ID、命令和日志。
- 若宿主已提供其他补充或自由输入，不重复添加同义入口。候选过多按真实条件缩小范围或按现有规则分页，不将当前页视为全部，不静默丢弃候选。
- 一次吸收整批明确答案及自由输入、普通文字中的额外事实，保留问题与答案的对应关系；已回答的缺口不重问，未回答项继续保留为缺口。
- 以最新有效提交中明确的修改为准。对象、范围或其他前提变化时，保留仍适用的事实，重新核对受影响答案与证据；不机械沿用旧结论，也不要求重答全部问题。
- 同次回答有矛盾或无法唯一映射时，只澄清冲突点。迟到或重复回复先核对当前任务，不让旧答案覆盖新事实或再次执行操作。
- 信息足够即按主流程继续，不新增“是否开始”或“信息是否正确”的关卡。用户取消就停止；未取得依赖答案时保持等待，不以时间流逝代替回答。

## 各能力的适用边界

以下按能力保留各自的特有节点；通用规则以上文为准，此处只写该能力的差异与边界。

### 起草

- 先读取用户输入、已读底稿和当前有效事实，列出真正缺失的起草立场及结构必要信息。已知不问，不把名称、金额、日期等可后补事实加入首稿前问题。
- 扫描所有必要缺口，而不是只取问题队列的第一项。若 B 依赖 A，而 C 与 A 独立，先问 A、C，收到提交后再决定 B。不因遇到 B 就把仍可同批询问的 C 推迟，也不提前猜 B 的选项。
- 基于底稿时先取得并读取文件；缺文件只引导上传，不能提前猜角色或搜索用户电脑。选择底稿与依赖底稿内容的问题不能放在同一批。
- 角色选项以当前已知交易为依据；合同类型未知时不提前固定买方／卖方等选项。适用时提供平衡立场，不能将未作答视为选择平衡。
- 只将含义明确、可以对应当前问题的内容记为已知；未回答项仍是缺口。对“还没问过立场”“没有回答立场”和“明确选择平衡”分别处理，不因为已完成类型询问就默认中性起草。
- 采购改为租赁等前提变化时，保留仍适用的事实，重新判断原有角色、立场和结构答案；不机械沿用不相容答案，也不要求重答全部问题。
- 结构足够且立场明确就直接生成完整初稿；只有仍阻断起草的缺口或冲突才继续按依赖合批询问，不增加信息收集完成后的确认关卡。
- 需要时可用一句业务语言承接已明确的类型和立场，随后直接出稿，不要求用户再次确认，不复述整套问答记录、不输出内部校验结论。存在未解决冲突时只询问冲突。
- 回答起草问题不代表授权发送合同、审批或签署。正式文件交付及签署确认继续遵循[文件交付与签署衔接](../products/draft/delivery-rules.md)，不因问答合批而跳过。

### 审查

- 多个真实候选且目标不明时先选文件；读取合同并识别实际角色后，才询问尚未明确的审查立场，提供真实角色及中立视角，不从上传者或文件名猜立场。已明确立场直接复用。
- 立场与其他已具备条件、互不依赖且确实阻断当前判断的事实可以合批；不将报告中的所有待确认事实都改成审查前必答题。关键事实有真实有限候选才使用选择题；识别不了角色时开放询问。
- 未回答立场不能当作选择中立；用户文字已明确角色或中立即继续。文件或立场变化时重评受影响结论，不要求重新回答仍有效的信息。
- 缺文件只引导提供；不问审查重点、签署阶段、报告格式或是否全面审查。报告中的非阻断疑点继续按[审查交付](../products/review/result-delivery.md)保留。

### 总结

- 仅在已有真实候选而指代无法唯一对应时澄清总结对象。已明确一份、某几份或全部时按原队列直接处理，不每份询问是否继续。
- 同一对象选择就是一个问题，不拆成多题；只有多个互不依赖的目标歧义才合批。缺材料只引导提供，不自行搜索候选。
- 不增加立场、长度、详略、字段偏好、格式或开始确认。目标明确即可读取、校验并在会话给概述和核心信息，不生成总结报告。

### 比对

- 仅澄清真实比对对象或方向歧义。超过两份且未指定组合时选择两份；支持多选时核对恰好两份，不支持时用文字收集两份文件名，不枚举全部组合。
- 比对方向依赖选定文件对，不能与尚未确定文件对的选择合批。用户一次明确了两份文件及方向时全部采用，不再问基准。
- 用户指定方向优先；未指定但上传或选择顺序可靠时第一份作基准并在结果说明，不新增确认。只有顺序也不可靠时，才从已定两份中选择基准。
- 不询问立场、报告格式、明细／总结模式。未知立场客观解释变化；用户明确只要总结就按原分支交付，不强制生成报告。

### 问答

- 已有多个真实文件或流程候选且问题指向不明时才选择对象；缺材料保留原问题并引导提供，不自行搜索、不索要内部 ID。
- 只有文件而没有问题时用一句开放提问了解用户想知道什么。若对象和问题均缺失、且问题表述不依赖对象，可在同一条文字中收集；不能为凑批次新增问题。
- “第一个”“刚才那份”能唯一对应当前对象时直接复用，连续追问不重选文件。正文与流程分别取证；目标或版本变化后重新核对相关依据。
- 不增加立场、回答模式、详细程度、开始确认或答后推荐问题。信息足够即回答，完整版本比对仍由对应实际可用能力承接。

### 发起管理

- 按[发起工作流](../products/manage/create-workflow.md)和[已有流程与审批工作流](../products/manage/manage-workflow.md)限定节点，不将所有业务分支组成问卷。“签合同”意图不明时先澄清分支，再组织分支问题。
- 发起中仅合批当前真实可问且互不依赖的缺口。例如必需审批流与发起部门的候选均已取得、且审批流不依赖部门选择时可合批；依赖主体、模板、文件或部门的候选必须待前提确定后取得。
- 模板选择和发送前完整信息继续用原文本流程；签署人及联系方式按原输入优先规则集中收集。多主体不触发额外选择，只有用户明确要求更换且目标不清时才询问。
- 管理与审批只澄清真实目标、范围或缺失动作。同意意见、拒绝与撤回原因按原规则用文字收集，不将尚未确定目标的意见与对象选择混合。只复用明确绑定当前目标与动作的意见。
- 明确“无意见／不填写”仍按审批规则传“无”；没回答不等于无意见。对象选择不额外授权业务动作，问答提交不替代当前完整配置的发送确认或服务端意愿认证；信息齐备且已授权的审批、撤回不新增确认。
