# 登录与恢复

仅用于本能力 实际访问 e签宝时的账号准备与恢复；登录不等于业务操作授权或完成签署、审批意愿认证。

## 执行环境与登录状态

登录、身份检查及后续业务命令在同一实际执行环境中完成。不得假定本机、远端容器或新会话共享登录状态；环境重建或切换后重新核对身份、企业与业务环境。只通过 CLI 管理登录，不读取、复制或迁移凭据文件，不把令牌写进本包或项目文件。状态无法持久保留时说明实际限制，不循环授权；登录成功不能替代业务确认。

## 检查与分步授权

1. 先按[CLI 检测与安装](cli-bootstrap.md)保证命令可用。粘贴正文、纯文本起草、正文修改和明确可本地完成的处理不前置登录。实际需要平台能力且本次没有已验证的有效身份，或业务明确返回未登录／过期时，执行 `esign auth status`。检查自身失败或信息不明不等于未登录，不循环授权；已有有效身份与环境直接继续。
2. 确认未登录或过期后执行 `esign auth login url --no-browser`，将返回的真实授权链接提供给用户，请其授权并回填本次授权码。保持已确认的 e签宝业务环境；仅在当前明确使用 e签宝沙箱或用户明确要求时加 `--sandbox`。Agent 的运行沙箱或受限环境不等于 e签宝业务沙箱，不能因此切换环境。
3. 收到用户为本次登录明确提供的授权码后执行 `esign auth login code --code '<本次授权码>'`。沙箱获取链接与兑换两步均带 `--sandbox`。授权码作为参数数据安全传递，只用于本次兑换，不回显、不写入脚本、交付文件或自行生成的日志；不索取密码、访问令牌，不读取凭据文件。取消、未回复、链接获取失败或宿主禁止执行时保留任务，不虚构授权成功。
4. 兑换后用 `esign auth status` 核实可用身份和环境。CLI 明确要求实名且返回真实入口时，提供入口等待处理，不反复登录。实名完成后用 `esign auth tenant list` 核对身份和真实企业候选；已有有效当前主体按本能力 原规则沿用，用户已明确目标则核对其可用性，需要选择时请用户从真实候选中选择，不擅自选第一家。需设置企业时使用 `esign auth tenant set '<tenant-id>'`，核对实际身份已变为目标；未验证当前命令契约时先读帮助。只有实际未登录或过期才重启登录。

## 恢复与失败分类

- 保存原请求、已确认事实、目标、当前文件版本和完成阶段，恢复后继续尚未执行的原步骤，不要求重新描述。
- 账号、企业或环境变化后重新核对平台引用、权限与待执行动作，旧身份下的 fileKey、流程、草稿或审批对象不能直接跨身份复用。保留仍适用的用户输入，不将旧对象的选择、意见或授权移给新对象。
- 仅当操作尚未调用或明确未执行时，恢复后继续。已调用的上传、转换、抽取或业务写操作出现超时、断连、结果不明时，先核对已有任务、产物或真实状态，不因重新登录重跑整条链路；缺少核查能力则说明结果待确认。纯只读状态核查可重试。
- 无权限、实名要求、业务限制、依赖缺失、读取失败分别处理，不通过重复登录、换企业、切生产或重装 CLI 试错。成功但空的数据与查询失败必须区分。
- 对用户只提供必要的授权／实名入口、具体缺口及可继续方式，不展示原始身份返回或内部日志。

文件抽取、转换或 OCR 的处理中状态与失败按[文档处理规则](document-processing.md)核对；已有可用正文或明确可纯本地读取的文件仍可按本能力 范围独立分析。

## 各能力衔接

- 起草：登录成功不等于用户确认生成文件、确认当前 PDF 或授权发起签署；涉及已确认文件的后续签署按[交付规则](../products/draft/delivery-rules.md)核对当前版本和用户意图。抽取、转换、登记或文件生成已超时、断连、结果未知时，先按[执行规则](../products/draft/execution.md)核对已有产物或真实状态；无法确认时说明受阻，不因为重新登录而重跑整条生成链路。
- 发起管理：发起的主体沿用、切换后重建和发送确认见[执行规则](../products/manage/execution.md)与[发起恢复](../products/manage/create-recovery.md)；管理和审批结果不明见[恢复规则](../products/manage/recovery.md)。账号登录不能替代[审批流程](../products/manage/approval.md)要求的业务认证。
