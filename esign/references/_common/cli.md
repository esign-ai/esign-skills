# CLI 文件与发送命令

本文件覆盖各能力的 CLI 取件与写操作命令：已选流程的文件获取、流程上下文与文件列表、取得选定文件、草稿／模板／发送。

仅为已明确的流程获取信息或取得已确定的文件；本文件不提供合同检索能力。用户上传文件直接进入对应能力流程；用户只要求解释命令时不执行。

业务调用使用执行环境提供的当前用户上下文。调用失败、无权限或环境不可用时，如实说明原因并停止受影响的操作，不扩大权限或切换身份。本地可访问文件无需执行本节。

参数取自用户已提供的真实标识、已有目标上下文或真实工具结果，使用参数数组或正确的 shell 转义，避免空格、单引号或含 `$` 的 fileKey 被解释为命令。以下值是形态示例，运行时必须替换。

## 流程上下文与文件列表

```bash
esign sign qa context --process-id '<真实processId>' --format json
esign sign qa file --process-id '<上下文中的真实processId>' --format json
```

前者用于状态及流程事实；后者用于文件元数据与角色，不是正文。按真实返回的文件容器和角色信息定位用户选定的合同文件及真实 `fileKey`，不假定固定字段一定存在，不假定所有响应都有相同容器，不自动补取独立附件。多个可能目标按当前能力的文件来源规则处理。

明确不可见、权限失败或文件不存在时停止相关读取。未返回字段不能推断；更不能自行扩大范围、切换账号或租户。

## 取得选定文件

```bash
esign file download --file-key '<真实fileKey>' --output-dir '<该文件本轮独立目录>'
```

- `fileKey` 使用文件列表或用户已有上下文中真实的值，不依据名称或路径拼接。
- 指定 `--output-dir` 是为了取得实际文件；只获取下载地址不等于完成文件读取。
- 核对退出状态、实际业务返回与本次目录中真实可访问的文件，不猜下载后的文件名或正文路径，保留文件标识与实际文件路径的对应关系。
- 每个目标文件使用独立目录；多个输出或文件归属不清时，核对实际结果后再读取，不自动选择第一份，不混用旧文件。
- 命令只返回 URL、异步状态、处理中、空文件或实际下载失败时，不能声称已经取得正文。说明未完成文件获取并停止依赖该文件的问题；其他独立文件可以继续。
- 文件是否需要重新获取按当前能力的文件来源规则处理；取得后回到该能力主体步骤继续读取与业务分析，不要求用户重复上传。
- 权限失败、不可见或不存在时停止受影响操作，不以失败冒充空结果，不尝试其他身份。

CLI 能力未知或参数不兼容时查看对应命令 `--help`，不每次检查版本、不自动升级或修改运行环境；如实反馈兼容性缺口。业务环境限制由部署方处理，不要求关闭 Agent 的执行隔离。命令返回结构不符合已知契约时，按实际输出核对，不能编造正文或字段。

## 草稿、模板与发送命令

仅在用户要求发送的范围内执行；当前身份、文件接入和展示见[执行规则](../products/manage/execution.md)。参数必须来自用户输入、真实文件或实际返回；JSON 使用序列化和参数数组或正确 shell 转义，不把姓名、文件名等拼成可执行代码。

### 创建与设置草稿

材料或模板已明确且实际身份可用后才创建；已有属于本任务、尚未发送且仍有效的草稿可复用，不为每次补信息创建新草稿。

```bash
esign sign draft start
esign sign draft set --draft-id '<实际draftId>' --files '<完整files数组>'
esign sign draft set --draft-id '<实际draftId>' --flow-template-id '<用户选择的真实模板ID>'
esign sign draft set --draft-id '<实际draftId>' --signers '<当前完整signers数组>'
esign sign draft set --draft-id '<实际draftId>' --process-name '<用户指定或已展示的流程名称>'
```

- `draftId` 来自真实创建结果；创建成功是草稿，不是已发起签署。
- `files` 每项包含真实 `file_key`、`file_name`；文件是否需上传按执行规则处理。按真实文件标识去重，不能从路径／名称猜标识。
- `signers` 使用本次选定的完整名单。企业字段：`type: enterprise`、`name`、`contactName`、`phone` 或 `email`。个人字段：`type: individual`、`name`、`phone` 或 `email`。未提供的可选字段省略，不传占位文字。修改时整体设置，不假设支持单元素局部更新。
- 审批流或发起部门按[确认规则](../products/manage/confirmation.md)判断实际必要性及有效选择。真实必选项尚未确定，或用户要求设置／更换时，取得本次实际可用列表供选择后，使用 `--approval-template-id`、`--initiator-dept-id` 实际设置；不能据名字猜 ID。列表仅从实际草稿／模板返回或已验证可用命令取得，无候选来源时不发明查询子命令。有列表不代表可省略审批；文件发送不无依据强加这两项，但真实必选仍需补齐。当前命令帮助明确：设置审批模板必须同时设置真实 `--initiator-dept-id`；部门未知时随审批选择一起补齐，不能猜部门 ID。
- 用户明确要求且当前命令支持时可设置 `--sign-order unordered` 或 `--sign-order sequential`；不让用户为默认设置多答一轮，不自造顺序含义或模板字段参数。

### 模板作为发送的一步

```bash
esign sign template select --flow-template-name '<用户提供的关键词>' --page-num 1 --page-size 50 --format json
```

关键词未提供就省略该参数。展示实际返回的可用模板并等待选择；有分页时不能把一页当全部。没有模板如实说明，不伪造默认模板。只有需要用户选择的真实模板列表，没有独立模板查询服务或独立查询后自动创建草稿行为。模板详情与默认配置仅使用实际返回或已有已验证能力，不发明额外子命令。

### 仅检查与真正发送

```bash
# 不发送，只检查草稿
esign sign draft submit --draft-id '<实际draftId>'
# 信息齐全、检查通过且用户授权覆盖当前配置后，真正发送
esign sign draft submit --draft-id '<实际draftId>' --yes
```

检查成功不能仅以存在卡片、URL 或零退出码判断；须同时核对实际业务结果。返回不符合已知结构时先核对实际帮助／返回，不猜字段、不把日志当结果。

成功后使用实际返回的 `longResultUrl` 或明确的用户查看入口；未返回链接时只报告可确认结果，不拼接 URL。不自动加命令帮助未支持的参数。当前能力明确不支持时友好说明，不用其他业务操作替代。
