# 问答场景

> 能力入口见 [问答能力](../products/query.md)。本文件是场景 recipe 表 + 深挖小节；通用规范（并行、翻页、ID 传递）见 [_common/conventions.md](_common/conventions.md)。recipe 为推荐组合（不吻合时可自行组合）；具体判断、边界与输出仍以能力主体及其引用规则为准。

| Recipe | 行动指南（推荐路线） |
|--------|-------------------|
| query-file-question | 1. 确定问题与目标：优先使用本轮上传、选中或明确指定的文件；「第二份」「刚才那份」「它」只复用当前会话真实对象映射，指向不明先澄清<br>2. 本地文件：`esign document extract-contract-body --file '<文件的真实可访问路径>'`；已选平台文件：`esign document extract-contract-body --file-key '<真实fileKey>'`<br>3. 读取与问题相关的条款及其条件、例外与文件内部交叉引用；表格保留行列关系、单位与注释<br>4. 对「有没有某种约定」等否定性结论，确认足够全文覆盖；缺页／截断只说明具体不能确认部分<br>5. 按 [回答规则](../products/query/answer-rules.md) 先直接回答，再给必要短引文或条款位置，答完即止 |
| query-from-process-file | 1. 已明确流程或其中的文件时：`esign sign qa file --process-id '<真实processId>' --format json` 取得流程内允许访问的文件信息<br>2. 按用户问题确定目标合同，多个可能目标让用户选择，不默认第一份或最新一份；本期不自动获取独立附件<br>3. `esign file download --file-key '<真实fileKey>' --output-dir '<本次文件的独立临时目录>'`，每文件独立目录<br>4. 核对本次文件实际可访问；仅有文件列表、标识、下载链接或任务状态不代表已取得正文<br>5. 取得文件后从 query-file-question 第 3 步起同 |
| query-process-status | 1. 已明确目标流程：`esign sign qa context --process-id '<真实processId>' --format json`<br>2. 按 [回答规则](../products/query/answer-rules.md) 的通用规则与流程证据规则，基于本次实际返回且可见的信息回答状态、参与人、签署及审批节点<br>3. 状态表述为「根据本次获取的流程信息」；仅在实际返回相应时间时引用，不编造更新时间<br>4. 未返回的意见、待办或其他字段只说明缺少信息，不猜测；流程截止时间不能当作正文付款或交付期限<br>5. 仅问流程状态时不下载正文、不要求文件条款或原文 |
| query-cross-file | 1. 围绕同一具体问题核对多个文件中的事实：分别取得各文件正文，先列各自事实再核对币种、税费、适用版本等口径<br>2. 存在冲突时说明冲突，不擅自认定主合同或「修订版」自动优先<br>3. 缺少必要对照来源时不给完整的一致或不一致结论，只回答已有依据支持的部分<br>4. 完整版本差异识别由 [比对场景](04-compare.md) 承接，不在问答中做全文比对 |
| query-followup | 1. 同一文件／流程的连续追问沿用本次已读取证据；「第一个」「刚才那份」能唯一对应当前对象时直接复用，不重选文件<br>2. 文件被替换、切换对象、账号或租户后，不沿用不属于新目标的正文或权限信息，重新读取并复核相关依据<br>3. 流程动态信息每次重新获取，不缓存旧状态<br>4. 不增加立场、回答模式、详细程度、开始确认或答后推荐卡片 |

## 否定性结论需全文覆盖

- 「没有某约定」「全文未见其他条款」须有针对性查找依据（已核对的相关条款与交叉引用），**不能用不相关条款证明全文没有**，更不能推成用户没有任何其他权利。
- 只在对目标事项有足够全文覆盖时才下否定结论；缺页／截断时只说明**具体**不能确认的部分，不固定列覆盖范围、已读页数或技术声明。
- 用户只问某条款就只答该条款，不顺带追加「全文未见其他约定」或模板页眉、签署栏、法务提示。

## 流程事实 vs 正文期限

- 文件事实来自实际读取的正文（条款、原文片段）；流程事实来自本次流程信息（状态、参与人、节点）。**两类来源分别注明依据**，不混用。
- 状态表述固定为「根据本次获取的流程信息」；仅在实际返回相应时间时引用，区分状态更新时间与节点操作时间，不编造更新时间。
- **流程截止时间不能当作正文的付款或交付期限**；反之正文条款也不能推断流程当前状态。两源冲突时分别陈述，不默认任一覆盖另一。
- 字段缺失／返回不完整／获取失败时，分别说明「本次流程信息未提供」「当前仅能查看……」或实际失败原因；**不把未返回待办、意见、签署记录解释成「没有待办」「无意见」「已全部签署」**。当前参与人清单≠完整历史。

## 跨文件对照口径

- 先列各文件各自事实，再核对币种、税费、金额、适用版本等口径是否一致；每项事实标注来源文件名。
- 冲突时说明冲突，不擅自认定主合同或「修订版」自动优先；缺少必要对照来源时只回答已有依据支持的部分，不给出完整的一致／不一致结论。
- 主体、金额、币种、税费、日期、生效条件一起核对，避免把押金当总价；能做的确定性计算交代所用数值与关系，不冒充原文载明。
- 完整版本差异全清单（新增／删除／修改／替换）不在问答承接，转 [比对场景](04-compare.md)。

## 关键区分

- **问答 vs 总结**：问答针对某个具体条款或事项作答，只答问题，不输出整份概述＋全字段摘要；总结面向整份合同。
- **问答 vs 审查**：问答据实回答条款或流程事实，不评风险等级、不给整体是否可签的结论；风险判断与修改建议由审查承接。
- **问答 vs 比对**：问答可围绕同一具体问题核对多个文件的事实；完整版本差异识别（新增／删除／修改／替换全清单）由比对承接。
- **问答 vs 发起/审批**：问答只读不写，不执行发起、签署、审批、撤回、催办；为回答问题临时取得文件不属于下载交付。
- **文件证据 vs 流程证据**：文件事实来自实际读取的正文，流程事实来自本次流程信息；混合问题分别取得依据并区分来源。
