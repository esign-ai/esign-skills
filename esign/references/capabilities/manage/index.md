# e签宝合同发起与管理

本能力由 mono 统一入口按意图加载，沿用 `esign` CLI 执行。跨能力续办时复用已确认的文件、流程、身份及已完成步骤，并继续读取 mono 内对应能力入口；不得虚构完成。

在 e签宝平台内发起签署流程，并查询、访问和处理已有合同流程及相关审批任务。按用户当前目标选择分支，先读取对应工作流，再执行其中的步骤和参考规则；不将所有分支串成固定流程。

## 任务分流

| 用户目标 | 必读工作流 |
| --- | --- |
| 把文件发给对方签署、用模板发起新的签署流程 | [发起合同](references/create-workflow.md) |
| 查合同、待我签署、列表进度、查看或填写、单份及批量签署入口、下载、撤回 | [已有流程管理](references/manage-workflow.md)，再按其中指引读取合同流程规则 |
| 待我审批、审批历史或入口、单条及批量同意或拒绝审批 | [已有流程与审批管理](references/manage-workflow.md)，再读取审批规则 |

“签合同”已明确指向新发起或已有流程时直接选择对应分支；无法判断时仅澄清这一点，不默认新建流程。“驳回”按真实审批任务和能力处理，不扩写为拒签或作废。仅咨询方法、要求方案或明确暂不执行时，不调用业务命令。

模板查询仅作为发起流程的一步，不提供独立查模板入口。

## 分支规则与上下文

- 发起分支沿用完整的信息补齐、草稿检查、发送确认及提交规则；既有流程与审批分支沿用各自授权、原因意见和认证规则。不得把发起确认套到普通查询，也不得用查询或对象选择代替发送确认。
- 发起、流程管理、审批之间切换时，保留用户原任务和已确认信息。草稿、合同流程、审批任务和模板分别保存真实标识及对象类型；不同列表的序号不能混用。对象、范围、账号、企业或环境变化时按对应分支重新核对，不跨目标沿用授权。
- 发起成功后保存实际返回的流程标识、名称、查看入口和当前执行身份；用户要求后续查询或处理时沿用有效目标，按管理分支取得当前状态和可用操作。只返回链接或草稿标识时，不猜流程标识；需要时按已有查询能力定位。不把发起成功说成签署完成，不自动执行用户未请求的后续操作。
- 生成单份或批量签署入口不代表完成签署；批量签署仍使用完整选中范围的一次调用并交付一个真实入口。审批意见、发送确认及批量处理的具体条件以对应工作流为准。
- 业务结果不明时按对应分支的恢复规则核查，不通过重放发送、撤回或审批命令查结果。原有套餐不足购买入口与草稿保留规则继续适用。

## 交互与其他能力衔接

只在所选工作流“结构化提问节点”列出的必要选择处，按[提问规则](references/question-rules.md)按依赖合批使用实际提问能力；不支持整批时在一条文字中收集。开放信息用文字收集，最终发送信息确认及模板选择沿用发起分支原有方式，不新增确认卡片或问题步骤。

起草、审查、总结、比对及合同问答继续由对应独立 Skill 承接。本包可展示查询列表中的状态，不因展示状态反复交接。用户要求查找后分析时，定位真实目标并传递文件或流程引用、版本、身份上下文及原问题，不把流程元数据当正文，不让用户重复原任务；缺少对应能力时如实说明。

起草交付并确认的当前有效文件进入发起分支，按原有规则核对签署配置，不重复上传。文件仍有待补充项时交回起草补齐，不拿旧稿发送。仅要求分析文件，不因此发起、审批或签署。

## CLI 与平台接入

需要 CLI、登录、环境或租户处理时，统一读取[CLI 基础能力](../cli/index.md)，完成后恢复当前流程。结果不明的业务操作仍先按分支恢复规则核实，不因重新登录重复提交。
